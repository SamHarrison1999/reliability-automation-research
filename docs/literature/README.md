# Literature review workspace

Phase 1 uses a scoping-review/evidence-mapping design. The protocol is in
[phase-1-review-protocol.md](phase-1-review-protocol.md). The operational
execution sheet is in
[phase-1-search-execution-plan.md](phase-1-search-execution-plan.md), with
search provenance in [search-log.csv](search-log.csv), screening decisions in
[screening-log.csv](screening-log.csv), and the chart in
[evidence-matrix.csv](evidence-matrix.csv).

The matrix is deliberately structured around the supervisor feedback. It
records the system studied, software domain, automation mechanism, empirical
method, data source, participants or operational subjects, metrics, human
factors, reproducibility information and limitations.

The current matrix remains a seed map, not a completed review. The provisional
map and PRISMA ledger make that boundary visible in
[literature-map.md](literature-map.md) and [prisma-flow.csv](prisma-flow.csv).
Records marked `abstract_only` require full-text verification before their
details can be used as established evidence. Records marked
`secondary_context_only` support citation chaining and terminology mapping but
are not primary empirical findings. No participant data or experimental
results are stored here.

Use [full-text-charting-guide.md](full-text-charting-guide.md) and
[claim-register.csv](claim-register.csv) to keep proposal claims traceable to
the source text. Do not add invented or unverified citations. Preserve DOI
links, database exports and search dates when the named database searches are
executed.
